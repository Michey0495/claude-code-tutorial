# 提案QAビルダー - プロジェクト規約

## 目的
RFPとヒアリングから、審査委員の想定質問と根拠つき回答案を作る。

## 回答トーン
- 結論を先に書く。理由は後
- 一般論で逃げない。提案内容に即した具体で答える
- 約束できないことは「現時点では未確定」と明示する。誇張しない

## 出典の付け方
回答末尾に `根拠: <資料名> / <該当箇所の引用 20〜40字>` を必ず付ける。
資料に書かれていない内容は回答にしない。推測が必要な箇所は「想定」と明記する。

## カテゴリ
体制 / スケジュール / 費用 / 技術 / 運用保守 / 実績 のいずれか。

## QAスキーマ
qa(id, category, question, answer, source, confidence)

- confidence: 高（資料に明記）/ 中（資料から妥当に導ける）/ 低（想定）

## 一貫性
同じ数値・前提を複数の回答で使う場合、値を揃える。矛盾が出たら資料に近い方を採用し、他を直す。

## コンテキスト方針
- 要約はRFPとヒアリングを別エージェント・別文脈で
- 質問生成と回答付与は要約結果と原資料だけを読む
