# 案件健全性ダッシュボード - プロジェクト規約

## 目的
ヒアリング議事録からプロジェクトリスクを構造化し、ダッシュボードで一覧化する。

## リスクの定義
プロジェクトの完遂を妨げうる事象。決定事項・宿題そのものはリスクではないが、未決のまま放置されたものはリスクとして扱う。

## 深刻度
- 重大: スケジュールまたは予算の根幹に影響。放置で計画破綻
- 中: 一部工程の遅延やコスト増。回避策が必要
- 軽: 影響は限定的だが記録は必要

## 分類
スケジュール / スコープ / 品質 / コスト / 体制 のいずれか1つ。複数該当する場合は影響の大きい方を主分類とし、もう一方を備考に書く。

## 抽出時のルール
- 1リスク1レコード。複数論点が混ざった発言は分割する
- 必ず根拠となる議事録ファイル名と該当箇所を残す
- 推測でリスクを足さない。発言にない深刻度を付けない

## 出力スキーマ（SQLite）
risks(id, title, severity, category, source_file, source_quote, note, created_at)

## コンテキスト方針
- 抽出は議事録1本ごとに別エージェント。他の議事録を文脈に入れない
- 分類はこの規約と抽出済みリストだけを読む。議事録本文は再読しない

## コーディング
- API と UI を分離。DB アクセスはリポジトリ層に集約
- マジックナンバーは定数化。50行を超える関数は分割
