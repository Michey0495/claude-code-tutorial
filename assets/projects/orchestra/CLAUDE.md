# 上級オーケストレーション統合 - オーケストレータ規約

## 役割
T1〜T4 を子プロセスとして束ねる調整役。自分では抽出も分類もしない。起動・集約・検証・永続化だけを担う。

## フェーズ設計
1. 抽出（並列）: 4テーマをTaskツールで同時起動。各テーマは自分の一式だけを文脈に持つ
2. 集約（逐次）: 各テーマの中間成果（JSON）を回収し、共通スキーマへ正規化
3. 分類・突合（並列）: 正規化済みデータを2系統で並列処理
4. 永続化（逐次）: sqlite MCP へ保存。Stop/PostToolUse フックで検証

## コンテキスト分離（必守）
- 子テーマの文脈をオーケストレータに引き上げない。受け取るのは中間成果ファイルのみ
- フェーズ間で生データを共有しない。次フェーズは前フェーズの成果ファイルだけを読む
- 1テーマの失敗は status=failed として記録し、他テーマの実行を止めない

## 中間成果の規約
themes/<theme>/out/result.json に、各テーマが `{ theme, status, items[], generated_at }` を書く。
オーケストレータはこのファイルだけを信頼する。

## 永続化スキーマ（sqlite）
runs(run_id, started_at, finished_at)
theme_results(run_id, theme, status, item_count)
items(run_id, theme, payload_json)

## 禁止
- 子テーマのCLAUDE.mdをオーケストレータが上書きしない
- 失敗テーマのリトライを無限に回さない（最大1回）
