# T5 上級オーケストレーション統合

T1〜T4の処理を1プロジェクトに束ねます。並列フェーズと逐次フェーズを混在させ、テーマごとにコンテキストを切り、フックとcronで自動で回します。最終成果物は複数テーマを束ねた自動処理パイプライン。

このトラックは T1〜T4 の一式を先に手元に置いてから取り組んでください。すべてローカルで完結します。組織名はすべて架空です。

## 前提

- T1〜T4 のいずれか（できれば全部）を一度通していること
- 学んでおく章: Subagents / 並列化戦略 / Fan-out / Hooks / MCP / Agent Teams

## 同梱物

```
orchestra/
├── README.md                 この手順書
├── CLAUDE.md                 オーケストレータの規約
├── ORCHESTRATION.md          パイプライン設計（並列/逐次/分離の定義）
├── .mcp.json                 filesystem + sqlite のMCP定義
└── .claude/
    ├── commands/run-all.md   1コマンドで全テーマを回す
    └── hooks/stop-summary.sh 完了時の自動サマリ
```

## 進め方

1. T1〜T4 の一式を `themes/` 配下に並べる（alpha / beta / gamma / delta）
2. `run-all` コマンドで4テーマの抽出フェーズをTaskツールで同時起動する（並列）。各テーマは独立コンテキストで、互いの中間結果を見せない
3. オーケストレータが各テーマの中間成果を回収し正規化する（逐次）
4. 集約結果を分類フェーズと突合フェーズで再度並列処理する
5. MCP(sqlite)へ保存。Stop+PostToolUseフックで成果物を自動検証する
6. `.mcp.json` と cron 雛形（ORCHESTRATION.md 参照）で定期実行に載せる
7. わざと1テーマの入力を壊し、他テーマに波及しないことを確認する

## 受入基準

- 4テーマを1つのコマンド系列で実行できる
- 並列フェーズが互いに独立したコンテキストで動く
- フックで成果物が自動検証される
- cron雛形で定期実行に載せられる
- 1テーマの失敗が他テーマに波及しない

## 比較の観点

並列化の効き（逐次との時間差）/ コンテキスト分離の徹底 / 自動検証の堅牢性 / 障害分離。
