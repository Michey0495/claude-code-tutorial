# パイプライン設計

## 全体像

```
[入力投入]
   │
   ├─ alpha 抽出 ┐
   ├─ beta  抽出 ├─ 並列（Taskツール / 独立コンテキスト）
   ├─ gamma 抽出 │
   └─ delta 抽出 ┘
        │
   [集約・正規化]            逐次（オーケストレータ）
        │
   ┌─ 分類フェーズ ┐
   └─ 突合フェーズ ┘        並列（フェーズ間は非共有）
        │
   [sqlite 永続化]           逐次
        │
   [Stop / PostToolUse 検証]
        │
   [cron で定期実行]
```

## 並列と逐次の使い分け
- 並列: テーマ間に依存がないフェーズ（抽出、分類/突合）。Taskツールで同時起動
- 逐次: 前フェーズの全結果が要るフェーズ（集約、永続化）

## コンテキスト分離の具体
- 各テーマは別エージェント。プロンプトに渡すのは自テーマの一式パスのみ
- オーケストレータは result.json だけを読む。テーマの会話履歴は引き継がない
- 分類と突合は別エージェント。互いの出力を入力にしない

## 障害分離
- result.json が無い／壊れている → そのテーマを status=failed で記録し継続
- 失敗テーマのリトライは最大1回。2回目も失敗なら skip

## cron 雛形（例）

```cron
# 毎営業日 朝に全テーマを実行（環境に合わせて調整）
0 8 * * 1-5 cd /path/to/orchestra && claude -p "/run-all" >> logs/run.log 2>&1
```

launchd / Windows タスクスケジューラでも同等。`claude -p` の非対話実行を定期トリガに載せるだけ。

## 検証フック
- PostToolUse: result.json が規約スキーマを満たすか即時チェック
- Stop: runs / theme_results を集計し、失敗テーマ数と総件数を要約出力
